# 白厄坐下动作、发衣与神情 · 第三版

本次针对坐下僵硬的反馈，直接重做原 MMD 骨架的表演。当前动画、音频和可编辑工程统一位于 `blender/build/phainon-film-v3`。旧版重复媒体与渲染帧已清理；动作生成仍需要的场景底稿保留为 `blender/source/phainon-wheat-base.blend`。

## 参考和技能

参考用户指定的[白厄动画](https://www.bilibili.com/video/BV14b3izbEfK/)，取得70秒公开参考，制作全片分镜采样与6–14秒的密集动作采样。重点观察视线、头肩、手势和表情变化的先后关系，以及身体停止后的发衣跟随。采样审看没有被当作逐帧复刻，原视频不随成片分发。

已读取本机 Aholo Lux3D 技能及其角色绑定与重定向说明，评估其适用范围。本项目采用本地 Blender 烘焙，保留现有 MMD 骨架、蒙皮、贴图和表情通道。F曲线批量写入使用 [Blender 分层动作 API](https://developer.blender.org/docs/release_notes/5.0/python_api/)。

## 动作

原动作在27–30.5秒整体降低中心骨，同时移动双脚，躯干与腿部缺少支撑关系。新版分解为看向座位、前倾、分脚调整、屈膝后移、扶座、接触缓冲、回正和放手。双脚在调整结束后由 IK 保持着地；身体包含很轻的呼吸和左右不完全同步的放松。

角色座位调整为独立圆木凳，旁边保留玩家的木座与围巾，给长衣摆留下自然垂落空间。手部扶座位置随凳面尺寸调整，落座后双手移回腿上。第一人称摄影机的坐低节奏与动作同步；另输出全身侧面审看，检查画面外的腿部和支撑。

## 发衣与表情

274根实际发束、披肩和衣摆骨骼参与次级运动。求解使用有静态造型预载的阻尼弹簧，区分头发和衣料刚度，加入轻风、骨链定长、关节活动范围与身体胶囊/圆凳接触代理；每帧4个子步。附加摆动的最终关节修正上限为0.15弧度（发束）和0.32弧度（衣料），防止碰撞修正导致短骨节突然翻折。

衣摆坐姿基形先沿大腿展开，次级运动在此基础上处理惯性。表情加入非等间隔、闭合快而睁开稍慢的眨眼，按对白阶段调整嘴角、眉眼和口型，头颈不再与躯干完全同幅运动。四段互动回应也继续运行次级运动。

这套方法属于 MMD 骨链物理与接触代理，并非全网格布料模拟，不能将代理接触统计当作整件衣服完全无穿插的证明。审看发现会拉扯衣料的座面几何修形已撤回，最终工程使用独立圆凳与相应的骨链碰撞代理。

## 核验与复现

`motion-readback.json` 从保存后的工程重新取样足部世界坐标、膝盖角度与实际变形后手部网格。`motion-report.json` 记录参与骨链、关节修正范围与表演采样；媒体导出另用 `verification.json` 核对时长、帧数及完整解码。

最终读回的植足阶段脚部最大位移约0.13毫米，30秒时双膝弯曲约106度。物理曲线经过四元数连续性修正，274根发衣骨骼的最大相邻帧旋转从约36.67度降至约4.58度；这是附加运动烘焙曲线的检查，不等同人体全部关节运动范围。

最终媒体已导出并核验：主片74秒、1776帧、1280×720、24 fps；四段回应分别5秒、120帧。带字幕版、互动主片及四段回应全部完整解码通过，网站已切换到 revision 3。22项后端/媒体/动作检查和14项前端检查通过，六个视频均支持 HTTP Range 读取。双视角审看视频为 `sit-motion-review.mp4`，8秒、192帧。

源文件：

- `blender/phainon_motion.py`：表演曲线、手臂解算与次级运动。
- `blender/enhance_phainon_motion.py`：生成第三版工程与审看帧。
- `blender/verify_phainon_motion.py`：工程读回和接触检查。
- `blender/smooth_phainon_secondary.py`：四元数连续性与逐帧转动幅度检查。
- `blender/render_phainon_motion_review.py`：25–33秒第一人称及全身动作预览。
- `blender/render_phainon_responses.py`：四段有发衣跟随的互动回应。

先生成工程，再执行 `smooth_phainon_secondary.py` 和 `verify_phainon_motion.py`。设置 `TREECOURT_FILM_SPEC=data/cinematics/phainon-wheat.json` 后，依次执行主片渲染、回应渲染与 `tools/finish_phainon_film.py encode`。清理后的渲染帧需要重新渲染后才能编码。两句已修复的选项配音与核对记录在 `voice-repair/`，并已同步至动画配音源文件；原始主对白的 SHA-256 留在 `source-audio-checksums.json`。
