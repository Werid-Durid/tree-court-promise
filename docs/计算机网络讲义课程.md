# 计算机网络讲义课程

入口：课程表 → 考研408 → 计算机网络 → 选择章节和知识点 → 从这里学习。

网络模块保留原六章和 56 个知识点 ID，每个知识点成为一个独立课时。每课包含三个教材小节（概念、机制、适用边界）、板书公式或过程、一份分步例题、一份原创迁移题和一份沿用原判题键的机制回顾，共 112 份配套练习，其中 56 份迁移题是本次新增。教材、例题、随堂练习可以自由切换；不以分数锁定下一课。

## 讲义依据与筛选

输入是用户提供的 1622 页图片型 PDF。原文件没有可提取的正文文本。构建时读取 PDF 书签形成页段索引，渲染各节汇总/过程页，用本机 Windows 中文 OCR 辅助检索，并抽查原图核对公式和协议流程。当前保存 141 页 OCR 记录，不宣称已经逐字 OCR 或人工核对全部 1622 页。

保留一份内容哈希一致的原件副本 `data/lectures/network/handout.pdf`，只读用于课内原页预览。原始微信文件保持不变。课程正文、例题、迁移题是重新编写的教学内容，没有把 OCR 错字直接当作教材。

筛选框架采用 408 网络六章结构：体系结构与性能、物理层、数据链路层、网络层、运输层、应用层。出版社公开复习目录用于对照主题：

<https://phei.com.cn/module/goods/wssd_content.jsp?bookid=68922>

**2027 正式大纲全文未取得，年度新增、删除与精确表述尚未逐条核验。** 映射文件明确保留此状态，不能称为完整官方大纲转写。

`knowledge/network_handout_mapping.json` 逐课记录 PDF 页段、教材化筛选状态及补充来源。IPv6、组播/IGMP/移动IP、SDN 等没有在这份讲义书签中找到独立节的内容，标明为补充考点，不冒充 PPT 原文。因特网历史、STP/VPN 配置细节和网页制作细节等只作辅助或查阅材料，不扩充为独立必修课时。

讲义中的历史细节另加注释。例如 PDF 第1107页列出的 ICMP 源点抑制不作为现行机制传授，参见 <https://datatracker.ietf.org/doc/html/rfc6633>。TCP RTO 的简化算例说明计时粒度及下界假设，避免把简化计算当作完整实现。

## 课堂与角色

阿那克萨戈拉斯讲概念与推演；风堇检查条件与易错边界；遐蝶作精炼辨析；白厄按例子复述。人物档案仍以 `characters/profiles.json` 为准，没有修改角色身份和关系逻辑。课堂沿用现有3D舞台、镜头与人物动作。

“打开完整教材”可集中阅读；“对照讲义原页”默认打开相关节最后的汇总页，可翻页或输入同一映射页段内的页码。页图接口只读取这一份固定 PDF，不接受任意文件路径。

新增的336段课堂台词保存在 `knowledge/network_course_voice_queue.json`，状态为待合成音频。语音播放继续要求角色和全文匹配，不用旧台词录音或系统 TTS 代替。

## 进度与判题

课时步骤和未提交答案存入 localStorage。迁移练习记录为 `course_attempt` 事件，保存原始输入，后端重新判题。机制回顾沿用已有 `attempt` 事件。两类练习共用同知识点每日好感贡献上限，选错不扣分，阅读和翻页不被记为已答题。

保留原有 `test`、`clues`、反馈与知识点 ID，因此原章节检测的历史成绩与已学记录不因升级重算。迁移练习结果不会冒充正式408考试分数。原六级/四级真题模块独立保留。

## 构建与验证

`knowledge/network_course_content.py` 保存教材、公式、例题、迁移练习和补充推导，关键字段以中文说明。运行：

```powershell
web/.venv/Scripts/python.exe knowledge/publish_network_course.py
```

更新 `data/curriculum/catalog.json`、`knowledge/network_course.json`、讲义映射、408课程镜像和配音文本队列。若先运行旧的四科基础课程发布脚本，需要再运行本脚本恢复网络教材层。网站启动时读取课程目录，发布后需重启。

回归验证覆盖：原知识点与判题键兼容、其他学科内容不变、所有课程字段、规范答案、全角与单位输入、服务端不信任客户端正确标记、每日贡献上限、数值模型、讲义页白名单及原件哈希。浏览器验证教材→例题→练习→反馈→下一课，原页查看、错答修正及刷新续学。

正式学习数据库的发布前一致性备份和重放核对位于 `knowledge/build/network-handout/before/`。独立浏览器验证使用8773端口及独立SQLite，不向正式档案写入测试作答。
